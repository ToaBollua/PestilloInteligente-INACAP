I. CRONOLOGÍA EVOLUTIVA DEL PROYECTO (DE MONO-NODO A DUAL-NODE)
Fase 1: El Incidente del Pulsador Físico (Mono-Nodo Arduino/ESP32) FALLO DE HARDWARE RESUELTO

El prototipo inicial (PestilloInteligente.ino) buscaba operar con un pulsador de entrada, dos LEDs y un micro-servomotor SG90.

Causa Raíz Documentada en BITACORA.md: El pulsador físico insertado en la protoboard generaba un cortocircuito mecánico permanente a GND, forzando el Pin de entrada a LOW constante. Las pruebas de aislamiento demostraron que el componente funcionaba puenteado en el aire pero colapsaba mecánicamente sobre las pistas de la placa.
Fase 2: Transición a Sensor Ultrasónico HC-SR04 y Cloud REST REFACTORIZACIÓN FUNCIONAL
  • Egreso Libre (Request-to-Exit): Se reemplazó el pulsador por el sensor ultrasónico HC-SR04 (Trigger en GPIO 5, Echo en GPIO 19). Si detecta presencia interior a < 8 cm, abre automáticamente sin esperar conexión ni autenticación de red (Safety / Seguridad Humana).
  • Enlace Firebase Realtime DB: Conexión HTTPS hacia https://pestillo-inteligente-default-rtdb.firebaseio.com/ consultando is_authorized.json.
  • Parche Crítico de SSL: Se erradicó el uso inseguro de setInsecure() en WiFiClientSecure, inyectando la validación del certificado raíz GTS Root R1 de Google Trust Services.
Fase 3: Arquitectura Distribuida Segura de Dos Nodos (ESP-NOW) ARQUITECTURA DEFENSIVA EF1

Para mitigar el vector de ataque de Manipulación Física del Bus de Actuación (donde un atacante exterior arranca el sensor y puentea el cable del servo para abrir la puerta), se dividió el sistema en dos microcontroladores:

Nodo / Rol Ubicación Física Interfaces / Periféricos Funciones de Seguridad
Nodo 1: ESP32_Sensor Exterior de la puerta (Perímetro) HC-SR04, Wi-Fi 802.11 b/g/n, ESP-NOW Lee ultrasonido, sondea Firebase REST con TLS, y transmite tramas ESP-NOW firmadas con HMAC-SHA256 y contador anti-replay.
Nodo 2: ESP32_Actuador Interior del chasis (Zona Segura) Servo SG90 (LEDC GPIO 18), LED Rojo (GPIO 23), LED Verde (GPIO 22), Capacitor 100µF Air-gapped (Sin Wi-Fi WAN). Valida la firma criptográfica ESP-NOW y manipula el PWM nativo (50Hz, 10-bit). Resorte mecánico Fail-Secure retorna el pestillo a 0° ante corte de luz.
II. ESPECIFICACIÓN FÍSICA Y PWM (ESP32 LEDC)
Matemáticas de Modulación de Ancho de Pulso (SG90 / MG90S) LEDC 10-BIT // 50 Hz

A diferencia de Arduino UNO (librería bloqueante Servo.h), en ESP32 se utiliza el hardware timer nativo ledcAttach / ledcWrite:

  • Frecuencia de Operación: f = 50 Hz ➔ Periodo: T = 20 ms (20,000 µs)
  • Resolución: 10 bits ➔ 2^10 = 1024 niveles (0 a 1023)
  • Posición 0° (Bloqueado / Cerrojo extendido): Pulso de 0.5 ms ➔ Duty = (0.5 / 20.0) * 1024 ≈ 26
  • Posición 90° (Desbloqueado / Cerrojo retraído): Pulso de 1.45 ms ➔ Duty = (1.45 / 20.0) * 1024 ≈ 74
  • Capacitor de Desacoplamiento: 100 µF / 16V en paralelo con la alimentación del servo para suprimir caídas de tensión inductivas (Brownout Reset).
III. MATRIZ DE VECTORES DE ATAQUE Y CONTRAMEDIDAS
Vector de Ataque Impacto Potencial Contramedida Implementada en Firmware
Man-in-the-Middle (MitM) en Firebase Intercepción y falsificación del estado is_authorized. Canal HTTPS estricto con validación de certificado raíz X.509 de Google Trust Services (GTS Root R1).
Ataque de Replay por Radiofrecuencia (ESP-NOW) Captura de paquetes inalámbricos de apertura y retransmisión para abrir la puerta. Criptografía simétrica HMAC-SHA256 con clave secreta compartida y contador incremental monotónico (Nonce/Seq). Paquetes duplicados o con seq ≤ last_seq son descartados de inmediato.
Sabotaje Físico Perimetral Desprendimiento del sensor exterior para acceder a los cables de control. Aislamiento de dos nodos. El cable del servomotor no cruza hacia el exterior; reside exclusivamente dentro del marco interior bajo control del Nodo 2.
Fallo de Energía / Blackout Puerta queda abierta o motor sin retención mecánica. Fail-Secure Físico: Resorte mecánico pasivo que traba el pestillo al cesar la energía electromagnética del servo.
